# Conformance suites

This directory holds the stress corpus (`stress/`) and the pinned upstream OpenRouter
specification (`openrouter/`) that the generator's semantic-adaptation layer is proven against.

## Stress fixtures

Each `conformance/stress/NN-*.yaml` file is a minimal, hand-written OpenAPI document (3.1, except
fixture 17 which is 3.0.x by design - see below) that isolates one construct the semantic model
must handle correctly. `ExperimentSupport.stressFixtures`
(`generator/openapi/src/test/kotlin/com/nabobery/sdkgen/openapi/ExperimentSupport.kt`) discovers all
17 fixtures by numeric prefix at test time, so every fixture is always covered by the deterministic
round-trip snapshot test even before it gains a dedicated assertion.

Every fixture's rendered `SnapshotRenderer` output is checked into
`generator/openapi/src/test/resources/snapshots/NN-*.txt` and compared byte-for-byte across two
independent adaptations and against the checked-in snapshot on every test run
(`SemanticModelTest."all seventeen stress fixtures adapt into deterministic snapshots"`). A snapshot
diff is the first signal of an unintended behavior change in the semantic adapter; regenerate
intentionally with `UPDATE_SNAPSHOTS=1 ./gradlew :generator:openapi:test`, and review the diff before
committing it.

`DiagnosticsTest."corpus stress fixtures remain lossless while diagnostic coverage is active"` only
exercises `ExperimentSupport.stressFixtures.take(5)` (fixtures 01–05); it is listed above only for
those fixtures.

`SemanticModelTest."every material semantic node has a non synthetic source location"` additionally
walks every stress fixture's adapted document and asserts that every `MaterialNode` carries a real
source location, so the corpus also backstops the source-mapping/provenance contract (ADR 0001) on
every run, not only for the OpenRouter document.

## Real-world conformance corpora

### OpenRouter

`conformance/openrouter/` pins the OpenRouter `openapi.yaml` (see `SHA256SUMS`) plus a generated consumer
module that exercises the SDK end-to-end across the supported test matrix.

### GitHub REST

`conformance/github/` pins the GitHub REST corpus, its lock/config and narrowly scoped runtime-semantics
overlay, one canonical generated snapshot, and a JVM consumer. The accepted Phase 3 state has 7,169 generated
Kotlin files, 139 exact accepted waivers, and zero active exclusions. The consumer covers Link-header pagination,
bearer authentication, typed errors, PATCH presence semantics, parameter encoding, and exact union behavior.
See `docs/phase3/results/t10-github-conformance.md`.

### Stripe

`conformance/stripe/` pins the Stripe corpus, exact waiver inventory, one canonical generated snapshot, and a
KMP consumer with a JVM conformance suite. The accepted Phase 3 state has 10,616 generated Kotlin files,
157 exact accepted waivers, and zero active exclusions. The consumer covers Stripe-compatible indexed form
arrays, typed maps, disjoint form unions, indexed multipart arrays, Basic authentication, and typed responses.
See `docs/phase3/results/t11-stripe-conformance.md`.
